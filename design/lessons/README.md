# Lessons

What we learned the hard way, by topic, so the next job of that kind starts smarter. Skills read the matching file before they plan (/brainstorm reads design.md, /rework-color reads design.md and engine.md, /ship-batch reads shipping.md, screen work reads screen.md).

One entry per lesson, newest at the bottom:
`- YYYY-MM-DD · what happened (one line) · the rule we take from it · where the rule now lives (file, check or "here only")`

- A lesson that changes how Claude talks or works with Cory also goes in .claude/rules/working-with-cory.md.
- When the same lesson lands twice, make it a check (a hook, a test, a script) and say so in the entry.
- Monthly: merge duplicates, delete what's no longer true. Superseded entries go to design/archive/.

Files: design.md (pitches, colors, cards, balance) · engine.md (rules code and tests) · screen.md (UI, motion, screenshots) · shipping.md (checks, publishing, releases) · harness.md (how threads work together).
