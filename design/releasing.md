# Releasing Cults

1. Intake every report into todo/audit/addendum with owner, exact behavior and completion check. Keep CHANGELOG.md player-facing; put technical evidence/risks in HANDOFF/in-flight/eval.
2. VERSION in src/v4/version.js is the single player-release version. Use patch for fixes/UI/wording, minor for a meaningful rule/content batch: `npm run version:v4 -- patch "Concrete change summary"` (or minor). It updates VERSION and adds an unreleased changelog section. Initial new scheme startsv0.6.0; do not bump again until that candidate is shipped or intentionally superseded.
3. Fill that section with final meaningful changes, not tool history. Never call an unreleased checkpoint shipped. Do not bump package.json as a substitute; that package version is not the game's display identity.
4. Commit source; check the exact immutable SHA with v4-check. Fix actual failures, refresh obsolete contracts/records only under explicit changed rules, retain independent coverage. Check actual desktop/phone UI, local/online full games and relevant animation overlap. Reserve quiet timing windows.
5. Publish `bash scripts/v4-play.sh <checked-full-sha>`. It rejects reuse of a published release number for a different commit and requires its changelog section, then exports that commit, builds and writes build.json with release version, full commit and build time; main/play is separate from source branch. Home/help show semantic version plus shortbuild reference. Save/room compatibility remains the rules-content hash.
6. Verify public build.json plus actual game UI. Mark changelog section shipped with source/main commit and checks. Update HANDOFF, in-flight, todo/audits and project-status; regenerate the conversation board. Announce “Shipped—ready to test” only now.
7. Do not include unrelated unverified edits in a deployment. Source checkpoint pushes for handoff are allowed when explicitly requested; clearly list blockers. Preserve prior verified public release if checks fail.

For a handoff include: exact source/live identifiers, failed checks with logs, no assumed running agents, next executable steps, unresolved decisions and cleanup status. No fabricated completion percentages or ETA.
